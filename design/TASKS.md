## 1. 백오피스 `/admin` — 최우선

지금 문의는 DB에 쌓이는데 볼 화면이 없습니다. 20건이 넘으면 관리가 무너집니다.

**범위**
- Supabase Auth 이메일 로그인 (담당자 전용)
- 요청 목록 — `rfq_board` 뷰 사용 · 상태별 필터 · 최신순
- 상세 화면 — 품목 명세 · 확인 문답 · 첨부 파일 다운로드 · 발송 후보 공급처
- 상태 변경 — 접수 → 확인중 → 발송준비 → 발송 → 회신취합 → 고객회신 → 종료
- 공급처 회신 입력 — `rfq_suppliers` 의 `unit_price` · `lead_time` · `replied_at`

**완료 조건**
- 로그인하지 않으면 아무것도 안 보인다
- 목록에서 상태를 바꾸면 DB에 반영된다
- 첨부 파일을 내려받을 수 있다
- `npm test` 통과

## 2. 접수 알림

문의가 들어온 걸 모르면 24시간 회신 약속을 지킬 수 없습니다.

**범위**
- Supabase Edge Function 또는 Database Webhook
- `rfq` insert 시 담당자에게 메일 발송
- 내용: 접수번호 · 연락처 · 품목 수 · 발송 가능 건수 · 백오피스 링크

**완료 조건**
- 테스트 문의를 넣으면 1분 안에 메일이 온다

---

## 3. 공급처 마스터 DB 이관

지금은 `src/engine/suppliers.js` 에 74곳이 상수로 박혀 있습니다.
거래처가 바뀔 때마다 코드를 고쳐 재배포해야 합니다.

**범위**
- `suppliers` 테이블에 현재 74곳 시드 입력
- 백오피스에서 추가·수정·비활성화
- `matchSuppliers()` 를 DB 조회로 전환 (단, 익명에게 목록이 노출되면 안 됨 → 매칭은 서버 함수로)

**완료 조건**
- 백오피스에서 공급처를 추가하면 다음 매칭에 반영된다
- 익명 사용자가 공급처 목록을 조회할 수 없다
