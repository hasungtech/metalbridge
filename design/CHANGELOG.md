## 2026-08-25 · 요청서가 견적 가능한 문서가 되도록 4가지 보강
운영자 지적 — 테스터 요청서(MB260825458)로는 공급처가 견적을 못 냅니다.

- **지름 목록 품목을 요청서에서 지름별 행으로 전개.** "Ø(13,…,46) 각 50본" 이
  한 행 `Ø13~46 (17종) · 50` 으로 나가 총량인지 지름당인지 알 수 없었습니다.
  이제 17행 × 각 50본으로 나가고 첫 행 비고에 "지름별 각 50 · 총 850".
  '각' 이 없으면 "총 n — 지름별 배분 확인" 을 남깁니다
- **길이가 요청서에 실립니다.** "4200L 기준" 이 판독만 되고 치수 칸에서
  사라졌습니다. 길이 값을 캡처해 카드와 요청서 모두 `× L4200` 표기
- **정밀 공차 후속 질문.** "정밀 공차 지정" 칩만으로는 가격이 안 나옵니다.
  고르면 값(h9 · ±0.1 …)을 되묻고, 요청 조건에 "정밀 공차 지정 — h9" 로 실립니다.
  도면 첨부로 갈음 · 모르겠습니다 선택지 유지 (사전 4개 언어)
- **연락처 형식 검증.** 테스터가 "1" 로 통과 — 회신을 전달할 수 없는 접수였습니다.
  이메일 또는 전화번호(숫자 8자리 이상)만 받고, 아니면 같은 질문에 머뭅니다
- 확인: npm test 20건 통과 (신규 3건 — 검증·후속 질문·행 전개는 실제 엑셀을

### SQL 을 실제 Postgres 16 에 돌려 검증하다 버그 3건을 잡았습니다
- **`qty` 제약이 틀림** — `rfq_items.qty` 는 integer 인데 `length(coalesce(qty,''))` 로
  text 취급 → 마이그레이션 자체가 실패. 정수 범위 검사로 수정
- **`INSERT ... RETURNING` 이 원래부터 실패하던 문제** — `submit.js` 의
  `.insert().select('id')` 는 SELECT 권한과 **SELECT 정책**을 둘 다 요구합니다.
